# ADR 001: OfficialRegistrationRecord as Aggregation Model

## Status
Accepted

## Context
Credentials require data from multiple disparate domains (Citizen Profile, Journey Dates, Vehicle Data). Passing multiple loosely-coupled stores directly into rendering components created massive prop drilling and race conditions.

## Decision
We introduced the `OfficialRegistrationRecord` in the Aggregation Layer. It acts as a standardized, read-only projection of the disparate domains.

## Consequences
- **Positive:** Rendering components now receive a single, stable data object.
- **Positive:** Decouples the UI from the underlying storage mechanism.
- **Negative:** Requires a translation step whenever underlying store schemas change.
